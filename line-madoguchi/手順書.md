# LINE万能受け口 構築手順書

> 「LINE窓口をひとつ作ります。現場のものを何でも投げてください。」
> 現場の写真・音声・メモをLINEへ → AIが読み取り・整形 → 使える形で返ってくる

## 成果物（3モード）

| モード | 入力 | 出力 |
|---|---|---|
| ① 見積下書き | 現調帰りの音声 | AnyONE取込用の見積下書きCSV（手打ちゼロ） |
| ② 被害報告書・写真台帳 | 被害箇所の写真＋一言音声 | 保険申請・罹災証明に添付できるPDF |
| ③ 施工事例記事化 | 完工写真 | ブログ記事の下書き（既存ブログ運用と合流） |

## 全体アーキテクチャ

```
現場スタッフ
   │ 写真・音声・テキストを送信
   ▼
LINE公式アカウント（Messaging API）
   │ Webhook
   ▼
GAS doPost ──即レス「受け付けました」(replyToken・無料)
   │ 受信キュー（スプレッドシート）に記録
   ▼
GAS 時間トリガー（1分ごと）でキュー処理
   ├─ メディア取得（LINE Content API）→ Google Driveへ保存
   ├─ 音声 → Whisper APIで文字起こし
   ├─ 写真 → Claude APIで内容読み取り
   └─ モード別に整形
        ├─ ①CSV生成（Drive）
        ├─ ②Slidesテンプレ→PDF書き出し（写真台帳）
        └─ ③Googleドキュメントに記事下書き
   │
   ▼
LINEへプッシュ通知「できました」＋成果物リンク
```

**なぜキュー方式か**: LINEのWebhookは数秒でタイムアウトする。doPostでは「受付」だけ返して即200を返し、重いAI処理は1分トリガーで非同期に行う。replyTokenでの即レスは無料、結果通知のプッシュは従量カウント対象（下の費用欄参照）。

## 技術スタック

- **LINE Messaging API** — 受け口。リッチメニューでモード切替
- **Google Apps Script** — Webhook・キュー処理・成果物生成（サーバー不要）
- **スプレッドシート** — 受信キュー・ユーザー状態・処理ログ
- **Claude API**（claude-sonnet-5 推奨）— 写真読み取り・テキスト整形・記事生成
- **OpenAI Whisper API** — 音声文字起こし（LINEの音声はm4a、そのまま投げられる）
- **Google Drive / Slides / Docs** — 成果物の保存・PDF化

---

## Phase 0: 準備（アカウント・キー）

1. **LINE公式アカウント**
   - クライアントの既存アカウントがあればそれを使う。なければ [LINE Official Account Manager](https://manager.line.biz/) で新規作成
   - [LINE Developers](https://developers.line.biz/) でMessaging APIチャネルを有効化
   - 控えるもの: **チャネルシークレット** / **チャネルアクセストークン（長期）**
   - 設定 > 応答設定: 「応答メッセージ」OFF、「Webhook」ON
2. **Anthropic APIキー** — [console.anthropic.com](https://console.anthropic.com/) で発行
3. **OpenAI APIキー** — Whisper用。[platform.openai.com](https://platform.openai.com/) で発行
4. **Googleアカウント** — クライアント側の管理アカウント推奨（成果物Driveの所有権のため）

## Phase 1: スプレッドシート＋GASプロジェクト

1. 新規スプレッドシート「LINE万能受け口_管理」を作成し、シートを3枚用意
   - `queue`: A:受信日時 / B:userId / C:messageId / D:type(text|image|audio) / E:モード / F:テキスト内容 / G:DriveファイルID / H:状態(pending|processing|done|error) / I:結果リンク / J:エラー内容
   - `users`: A:userId / B:表示名 / C:現在モード(mitsumori|higai|jirei) / D:最終操作日時
   - `log`: 処理ログ（デバッグ用）
2. 拡張機能 > Apps Script でプロジェクト作成 → `Code.gs`（同フォルダの雛形）を貼り付け
3. スクリプトプロパティに登録（プロジェクトの設定 > スクリプトプロパティ）
   - `LINE_CHANNEL_SECRET`
   - `LINE_CHANNEL_ACCESS_TOKEN`
   - `ANTHROPIC_API_KEY`
   - `OPENAI_API_KEY`
   - `DRIVE_FOLDER_ID` — 成果物・受信メディアの保存先フォルダ
   - `SLIDES_TEMPLATE_ID` — 写真台帳テンプレ（Phase 4で作成）
4. デプロイ > 新しいデプロイ > **ウェブアプリ**
   - 実行ユーザー: 自分 / アクセス: **全員**
   - 発行されたURLをLINE DevelopersのWebhook URLに設定 → 「検証」で成功を確認
5. トリガー設定: `processQueue` を **時間主導型・1分おき** に登録

## Phase 2: リッチメニュー（モード切替）

LINE Official Account Manager > リッチメニューで3ボタンを作成:

| ボタン | タイプ | テキスト |
|---|---|---|
| 見積下書き | テキスト送信 | `#見積` |
| 被害報告 | テキスト送信 | `#被害` |
| 施工事例 | テキスト送信 | `#事例` |

GAS側は `#見積` 等を受けたら `users` シートのモードを更新し、「見積モードです。現調の音声を送ってください」と案内を返す。以降そのユーザーの写真・音声は選択中モードで処理される。

## Phase 3: AI処理パイプライン

- **音声**: LINE Content APIでm4a取得 → Driveに保存 → Whisper（`whisper-1`、language=ja）で文字起こし → モード別プロンプトでClaudeに整形依頼
- **写真**: Content APIでjpeg取得 → Drive保存 → Claude（image入力）で「写っている被害/施工内容の説明文」を生成
- **テキスト/一言音声**: 直前の写真への注釈として扱う（②モードでは「写真＋一言音声」がワンセット）

モード別プロンプトの要点（詳細はCode.gs内）:

- **①見積**: 文字起こしから「工事項目 / 数量 / 単位 / 単価（不明なら空欄） / 備考」を抽出しJSON→CSV化。**勝手に単価を創作しない**、聞き取れなかった項目は備考に「要確認」と書く
- **②被害報告**: 写真ごとに「撮影箇所 / 被害状況の客観的描写 / 一言音声の内容」を整理。保険申請に使うため**推測や誇張をしない**文体
- **③事例記事**: 完工写真から「工事内容の見出し / 本文600〜800字 / ビフォーアフターの説明」をブログ調で生成（既存ブログのトーンに合わせたサンプル記事を2本プロンプトに入れる）

## Phase 4: 成果物生成

1. **①CSV**: `Utilities.newBlob(csv, 'text/csv')` でDriveに保存 → 共有リンクをLINEへ。
   ⚠️ **AnyONEの見積インポート仕様（列構成・文字コード）をクライアントに確認してから列を確定する**。仕様が取れるまでは汎用列（項目/数量/単位/単価/金額/備考）で仮組み
2. **②写真台帳PDF**: Googleスライドでテンプレを1枚作る（1スライド=写真2枚＋物件名・撮影日・説明欄のプレースホルダ `{{photo1}}{{caption1}}...`）→ GASでテンプレをコピー → 写真差し込み → `exportLinks` でPDF化 → Drive保存 → リンク返信
3. **③記事下書き**: Googleドキュメント新規作成 → 本文流し込み＋写真挿入 → リンク返信。既存ブログ運用（auto-blog-generation）に流す場合はそのスプレッドシートに行追加でも可

## Phase 5: テスト → 納品

テストケース（自分のLINEで全部通す）:

- [ ] `#見積` → 音声60秒 → CSVが返る。数量・項目が音声と一致、創作単価がない
- [ ] `#被害` → 写真3枚＋一言音声 → PDF台帳が返る。写真と説明の対応が正しい
- [ ] `#事例` → 写真2枚 → 記事下書きDocが返る
- [ ] モード未選択で写真を送る → 「モードを選んでください」と案内が返る
- [ ] 長い音声（3分超）・大きい写真でもエラーにならない
- [ ] エラー時に `queue` のH列が `error` になり、ユーザーに「失敗しました」通知が届く

運用・費用の目安:

- LINE: 応答（replyToken）は無料。結果通知のプッシュはカウント対象 — 無料プラン200通/月。月200件超えるならライトプラン（5,000通/月・約5,000円）
- Claude API: 写真1枚＋整形で数円程度。Whisper: $0.006/分
- GAS: 無料（UrlFetch 2万回/日の枠内で十分）

## クライアント要確認リスト（着手前に回収）

1. **AnyONEの見積CSVインポート仕様**（列・文字コード・そもそもCSV取込ができるプランか）← ①の成否を握る最重要項目
2. LINE公式アカウントの有無・管理権限
3. 写真台帳の指定様式（保険会社・自治体指定のフォーマットがあるか）
4. 既存ブログのURL・トーン参考記事
5. APIキーの費用負担と発行主体（クライアント名義推奨）
